# JustPay — учёт цифровых подписок

Учебное приложение компании «Эридиан» (проект «Студенческий Android стартап»).
JustPay собирает подписки в одном месте: показывает, за что списываются деньги, сколько это стоит,
когда пройдёт следующий платёж, и считает общую сумму расходов в месяц. Любую подписку можно
приостановить и возобновить. Для каждой подписки настраивается дата уведомления об оплате, а в
карточке подписки видно, как часто ей пользуются, и ведётся серия дней подряд.
Все основные функции работают без интернета, сеть нужна только для курса валют при смене валюты.
Вход выполняется в локальный аккаунт, который хранится в базе на телефоне.

Разрешения Android (других нет):

| Разрешение | Зачем |
|---|---|
| `POST_NOTIFICATIONS` | показать напоминание об оплате (запрашивается окном, Android 13+) |
| `RECEIVE_BOOT_COMPLETED` | заново завести напоминания после перезагрузки |
| `INTERNET` | получить курс валют Банка России, когда пользователь меняет валюту аккаунта (только тогда) |
| `PACKAGE_USAGE_STATS` | особый доступ, пользователь включает его сам в настройках; нужен, чтобы считать открытия и время в приложениях сервисов, которые он привязал к подпискам. Без него работают ручные отметки |

Видимость приложений для выбора сервиса задана через `<queries>` (приложения с значком запуска),
широкое разрешение `QUERY_ALL_PACKAGES` не используется.

Демо-данных в приложении нет: новый аккаунт пуст. Примеры на экране знакомства вымышленные.

## Технологии

Java 17 (язык исходников), XML и Android Views, SQLite через `SQLiteOpenHelper`, `SharedPreferences`.
Kotlin, Compose, WebView и сторонние библиотеки не используются. Зависимостей в `build.gradle` нет.

## Сборка и установка

1. Откройте папку `JustPay` в Android Studio (File → Open) и дождитесь синхронизации Gradle.
2. Запустите эмулятор или подключите телефон с включённой отладкой по USB.
3. Нажмите Run (зелёный треугольник) либо соберите APK из консоли:

   ```
   gradlew.bat assembleDebug
   ```

   Готовый файл: `app/build/outputs/apk/debug/app-debug.apk`.
4. Установка APK вручную: `adb install -r app-debug.apk`.

Если Android Studio не нашла SDK, она сама создаст `local.properties` с путём к нему. Этот файл,
а также папки `build` и `.gradle` в архив для сдачи не включаются.

|---|---|
| Создание записи (больше трёх полей) | `EditActivity`: название, стоимость, период, дата списания, категория |
| Список и карточка записи | вкладка «Главная» (`HomeTab`), `DetailActivity` |
| Редактирование | кнопка «Изменить» в карточке, тот же `EditActivity` |
| Удаление с подтверждением и отменой | «Удалить из JustPay» → шторка с кнопками «Отмена» и «Удалить» |
| Поиск и фильтрация | поле поиска по названию и фильтр «Все / Активные / Пауза» на главной |
| Проверка ввода | пустое название, сумма не больше нуля и не выше 1 000 000 ₽, дата не в прошлом |
| Сохранение после перезапуска | SQLite, таблица `subscriptions` (`SubscriptionDbHelper`, `SubscriptionRepository`) |
| Дополнительная функция | смена статуса «активна / приостановлена» и сумма расходов в месяц |
| Сведения о приложении | вкладка «Профиль» → «О приложении» |

Правило расчёта суммы в месяц: считаются только активные подписки; годовая цена делится на 12,
недельная умножается на 52 и делится на 12. Приостановленные подписки входят в «экономию».

Сообщения для пустого списка, пустого поиска и ошибок ввода предусмотрены. Дополнительно есть
календарь списаний на шесть месяцев, аналитика по категориям, уведомления внутри приложения
(без системных пушей), тёмная и светлая темы.

## Аккаунты и данные

Вход настоящий, но локальный: аккаунты существуют только на этом телефоне и никуда не отправляются.

- **Регистрация:** имя, электронная почта (не проверяется), пароль не короче 6 символов с повтором.
- **Хранение пароля:** в базе лежат соль и хеш PBKDF2-HMAC-SHA256 (120 000 итераций, своя соль у каждого
  аккаунта), сам пароль не сохраняется, восстановить его нельзя (`PasswordHasher`, `AccountRepository`).
- **Вход:** неверная почта и неверный пароль дают одинаковый ответ; после 5 неудачных попыток вход
  блокируется на 30 секунд.
- **Сессия:** номер аккаунта в `SharedPreferences`; «Выйти» в профиле стирает его и убирает напоминания.
- **Удаление аккаунта** (профиль → «Удалить аккаунт и все данные») каскадно удаляет его подписки и
  статистику.
- **Пустой аккаунт:** при регистрации не создаётся ни одной записи, демо-данных в приложении нет.
  Подписки, способы оплаты (просто подпись вроде «Основная карта», без номера) и отметки пользователь
  добавляет сам.

Таблицы SQLite (`JustPayDbHelper`, версия 4, включены внешние ключи):

```
accounts       _id, name, email (уникальна), pwd_hash, salt, iterations, created_at, avatar, currency
subscriptions  _id, account_id -> accounts, name, mark, price, cycle, next_date, prev_date, category,
               status, card, since, remind_days, app_package, created_at
usage_days     sub_id -> subscriptions, day, auto_opens, auto_seconds, manual   (ключ: sub_id + day)
```

При обновлении со старой версии (до аккаунтов) прежние демо-подписки удаляются: у них не было владельца.
Обновление с версии 3 на 4 просто добавляет аккаунтам аватар и валюту по умолчанию.

## Аватар и валюта

Оба параметра хранятся в таблице `accounts`, то есть у каждого аккаунта свои.

- **Аватар** (профиль → «Сменить аватар»): 6 цветов, 6 знаков в стиле «Эридиан» (инициалы, планета,
  звезда, луна, комета, кольцо) или собственная фотография. Есть предпросмотр, сохраняется кнопкой
  «Сохранить». Знак хранится строкой вида `planet:3` (`AvatarSpec`).
  - **Фото** выбирается системным окном выбора картинки (`ACTION_GET_CONTENT`), поэтому разрешение на
    доступ к галерее не нужно. Картинка читается с уменьшением, поворачивается по EXIF, обрезается до
    квадрата по центру, сжимается до 320 px и сохраняется JPEG-файлом в приватной папке приложения
    (`files/avatars/<номер аккаунта>.jpg`). Данные съёмки (место, время) при этом теряются, исходный файл
    не копируется. Фото не попадает в базу и не покидает телефон, удаляется кнопкой «Удалить фото» и
    вместе с аккаунтом (`AvatarPhoto`).
  - Нужно использовать только свои фотографии или фотографии с согласия изображённых людей
    (Положение, раздел 7); публикации в приложении нет.
- **Валюта** (профиль → «Оплата» → «Валюта»): рубль, доллар США, евро, тенге, белорусский рубль, гривна
  (`Currency`). Символ валюты подставляется везде: на главной, в списке, календаре, аналитике,
  карточке, форме, шторках и уведомлениях.
  - **С интернетом** цены подписок пересчитываются по курсу Банка России. Шторка показывает курс, дату
    курса и пример (например, 799 ₽ станет 9,92 $) и просит подтверждения. Курс берётся одним запросом
    к `https://www.cbr.ru/scripts/XML_daily.asp` (`ExchangeRates`), через рубль можно перевести любую пару
    валют приложения. Валюта и цены меняются одной транзакцией, цены округляются до копеек и не
    становятся нулевыми. Серверу не передаётся ничего, кроме самого запроса.
  - **Без интернета** (или если сервер недоступен) конвертация не работает. Шторка прямо говорит об этом
    и предлагает сменить валюту **без пересчёта**: цены останутся прежними числами, их нужно проверить
    вручную. Старые сохранённые курсы не используются, чтобы не пересчитывать по устаревшим данным.
  - Если в аккаунте нет подписок, валюта меняется сразу, сеть не нужна.
  - При обратном пересчёте возможны небольшие расхождения из-за округления до копеек.
  - Рубль и тенге показываются без копеек в итоговых суммах, остальные валюты с центами; цена подписки
    показывает копейки, если они есть.

## Использование подписок и серия

В карточке подписки блок «Использование». Источник данных у каждой подписки свой:

1. **Приложение сервиса на телефоне.** Кнопка «Подключить приложение» открывает список установленных
   приложений (подходящие по названию идут первыми). После включения доступа к статистике JustPay
   читает системные события `UsageStatsManager` и считает, сколько раз приложение открывали и сколько
   времени оно было на экране. Читаются данные только привязанных приложений, ничего не уходит в сеть
   (`UsageSync`, `AppCatalog`). Android хранит события около недели, поэтому дни копятся в таблице
   `usage_days` при каждом открытии JustPay, а записанные ранее дни не затираются.
2. **Ручные отметки.** Если у сервиса нет приложения, кнопка «Пользовался сегодня» добавляет отметку,
   её можно убрать. Отметки учитываются и у подписок с подключённым приложением.

Что считается (`UsageMetrics`): использований за 30 дней (открытия плюс отметки), время в приложении,
цена одного использования (месячная стоимость делится на число использований), дата последнего раза.

**Серия** — наша версия идеи из Duolingo. Каждый день, когда подпиской пользовались, получает звезду
из знака «Эридиан». Серия — это число таких дней подряд. Если сегодня отметки ещё нет, серия не
обрывается до конца дня, но подсказка просит её продолжить. Показываются рекорд и неделя звёзд. На
вкладке «Аналитика» своя общая серия (день засчитывается, если пользовались любой подпиской) и список
подписок, по которым две недели нет активности: сколько они стоят и предложение поставить на паузу.

## Напоминания об оплате

В форме подписки блок «Напомнить об оплате» имеет три режима:

- **Как в профиле**: уведомление за столько дней до списания, сколько выбрано в профиле (1, 3, 7 или свой срок от 0 до 60 дней);
- **Своя дата**: пользователь выбирает день уведомления от сегодняшнего до даты списания;
- **Выкл**: по этой подписке уведомлений нет.

Своя дата хранится как число дней до списания (`remind_days` в таблице), поэтому при регулярном списании
напоминание само переезжает на следующий период. Уведомление приходит в 09:00 выбранного дня. Его же
видно в карточке подписки, там можно быстро перейти к изменению.

Как это устроено: `ReminderScheduler` заводит один будильник `AlarmManager` на ближайшее напоминание
(неточный, `setAndAllowWhileIdle`, поэтому специальное разрешение на точные будильники не требуется),
`ReminderReceiver` показывает уведомление и ставит следующий будильник, `SystemEventsReceiver`
восстанавливает будильник после перезагрузки, смены часового пояса и обновления. Уведомление о
каждом списании отправляется один раз. Из-за неточного будильника система может сдвинуть показ на
несколько минут.

## Системные уведомления

В приложении три вида уведомлений Android (разрешение `POST_NOTIFICATIONS` на Android 13+). Каждый вид
можно выключить в профиле, а в настройках телефона у них два отдельных канала.

| Уведомление | Канал | Когда приходит |
|---|---|---|
| О предстоящем списании | «Напоминания о платежах» | в 09:00 дня напоминания: «как в профиле» (1, 3, 7 дней или свой срок), своя дата подписки или выключено |
| Серия под угрозой | «Серия и активность» | в 20:00, если сегодня нет отметок использования, а серия не нулевая. Пропущенную проверку можно выполнить позже, но не после 23:00 |
| Подписки без активности | «Серия и активность» | в 12:00, не чаще раза в неделю, если есть активные подписки старше двух недель без использования 14 дней и дольше |

Условие проверяется в момент срабатывания, а не при планировании: к вечеру отметка могла появиться (перед
проверкой серии JustPay заново читает статистику привязанных приложений). Проверка выполняется один раз в день
и не повторяется, если причин для уведомления нет. У каждого вида свой неточный будильник (`DailySchedule`,
`ActivityReminders`, `ReminderScheduler`), после перезагрузки они заводятся заново. Все напоминания работают только
для аккаунта, в который выполнен вход. Нажатие на уведомление про серию или неиспользуемые подписки открывает
вкладку «Аналитика». Правило «неиспользуемая подписка» общее с экраном «Аналитика» (`UsageInsights`).

## Известные отличия от дизайна

- Шрифты Manrope (текст) и Unbounded (крупные цифры и заголовки) лежат в `res/font` и подключены
  в стилях `Jp.Text`, `Jp.Semi`, `Jp.Bold`, `Jp.Disp`. Это вариативные шрифты: нужное начертание
  задаётся через `fontVariationSettings` в `res/font/*.xml`.
- Добавлены поле поиска и кнопка «Изменить»: их требует Положение, в макете их не было.
- Напоминания о платежах настраиваются отдельно для каждой подписки (в макете была одна общая
  настройка в профиле), см. раздел ниже.

## Правовая памятка (кратко)

Приложение не выполняет платежей, не собирает и не передаёт персональные данные, не требует
регистрации. Данные хранятся только на устройстве. Перед коммерческим запуском нужно решить
вопросы, перечисленные в разделе 7 Положения: оператор персональных данных, основание и срок
хранения, лицензии материалов, правила размещения рекламы.
